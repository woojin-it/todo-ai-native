# UI 가이드라인

My ToDo 화면의 디자인 규칙입니다. 토큰은 모두 `frontend/src/index.css`의 `:root`에 정의되어 있으며, 새 컴포넌트는 하드코딩 색상 대신 이 토큰을 사용합니다.

## 1. 디자인 원칙

- **오늘 얼마나 끝냈는지가 먼저 보인다.** 강조 요소는 작업 수만큼 나뉜 원형 프로그레스 하나뿐이고, 나머지는 조용하게 둔다.
- **색상 하나에 의미 하나.** 같은 색을 장식에 재사용하지 않는다.
- **상태는 구조로 표현한다.** 그림자, 그라데이션 같은 장식 대신 배경·테두리 차이로 상태를 구분한다.

## 2. 색상 (Color System)

| --- | --- | --- | --- |
| `--paper` | `#f3f5f7` | `#12161b` | 페이지 배경, 완료된 카드 배경 |
| `--surface` | `#ffffff` | `#1b2128` | 카드, 입력창 |
| `--ink` | `#17202b` | `#e6eaef` | 본문, 주요 버튼(추가·저장) |
| `--slate` | `#5b6675` | `#98a3b0` | 보조 텍스트, 카드 안 보조 버튼 |
| `--line` / `--line-strong` | `#dde2e8` / `#b9c1cb` | `#2b333d` / `#46515e` | 카드 테두리 / 입력창·체크박스 테두리 |
| `--track` | `#e3e7ec` | `#2b333d` | 진행 막대의 빈 칸 |
| `--hover` | `#eceff3` | `#242b33` | 고스트 버튼 호버 배경 |
| `--priority-high` / `-bg` | `#9a4a05` / `#fcecd9` | `#f4a865` / `#3b2816` | **우선순위 "높음" 배지 전용** (호박색, `--danger`와 구분) |
| `--priority-medium` / `-bg` | `#4b45a3` / `#ebeafa` | `#aaa5f5` / `#29274a` | **우선순위 "보통" 배지 전용** (남보라, `--focus`와 구분) |
| `--priority-low` / `-bg` | `--slate` / `--hover` | 같음 | 우선순위 "낮음" 배지 |

글자 크기는 `--text-xs` 12px(배지), `--text-lg` 20px(섹션 제목, 통계 값)를 추가로 쓴다.
| `--pine` | `#1e7350` | `#5cc493` | **완료 상태 전용** (체크박스, 취소선, 진행 칸) |
| `--danger` | `#b4362a` | `#f08a7c` | 삭제 버튼의 호버·포커스, 오류 알림 테두리, 입력 검증 오류 문구·테두리, 지난 마감 표시 (파괴적 동작·실패·기한 초과, spec-review R-23) |
| `--focus` | `#1d6bf3` | `#7ab0ff` | **키보드 포커스 링 전용** |

다크 모드는 `@media (prefers-color-scheme: dark)`에서 같은 토큰을 재정의합니다. 날짜 선택기 같은 네이티브 컨트롤도 테마를 따르도록 `:root`에 `color-scheme`(light/dark)을 함께 지정합니다.

## 3. 타이포그래피 (Typography)

- 서체: IBM Plex Sans KR 한 가지만 사용 (`index.html`에서 Google Fonts로 로드)
- 굵기: 400(본문), 500(버튼·진행률 문장), 700(제목)
- 크기: `--text-sm` 14px(보조·버튼), `--text-md` 16px(본문), `--text-xl` 28px(제목, 자간 -0.02em)
- 숫자가 바뀌는 곳(진행률, 마감 표시, 날짜 입력)은 `font-variant-numeric: tabular-nums`로 폭을 고정한다.

## 4. 간격 (Spacing)

`--space-1`~`--space-7` = 4 / 8 / 12 / 16 / 24 / 32 / 48px. 카드 사이 8px, 영역(헤더·진행률·입력) 사이 24~32px.

모서리 반경은 위계에 따라 다르게 쓴다: 카드 `--radius-card` 12px, 입력·버튼 `--radius-control` 8px, 진행 칸 `--radius-segment` 3px.

| 대시보드 레이아웃 | 880px 이상 2열(왼쪽 300px `.sidebar`: 헤더 → 원형 → 통계 카드, `position: sticky` / 오른쪽 `.tasks`: "오늘의 작업" 제목 → 입력 폼 → 상태 필터 탭 → 목록), 최대 너비 1040px. 880px 미만은 같은 순서의 1열(최대 600px) |

| 입력 폼(Task Form) | 두 줄. 1줄: 높이 48px 입력창 / 2줄: 왼쪽 `.form-fields`("카테고리" `<select>`, "우선순위" `<select>`, "마감일 (선택)" `<input type="date">`), 오른쪽 잉크색 "추가" 버튼(40px, 줄이 넘어가도 `margin-left: auto`로 오른쪽). DOM 순서 = Tab 순서(입력 → 카테고리 → 우선순위 → 마감일 → 추가). 입력 검증 오류가 있어도 버튼은 활성(목록 로딩·요청 중에만 비활성). 누르면 요청 대신 입력창 아래 오류 문구를 보여 준다(아래 "입력 검증 오류"). 추가에 성공하면 텍스트와 날짜는 비우고 카테고리·우선순위는 유지한다 |
| 보조 입력 (FR-012, FR-013, FR-015) | `.field` = 보이는 라벨(`.field-label`, `--text-sm`, `--slate`) + 컨트롤. `.select-input`·`.date-input`: 높이 40px, `--surface` 배경, 1px `--line-strong` 테두리, `--radius-control`, `--text-sm`. 포커스는 텍스트 입력창과 같은 규칙(offset 0 + 테두리 `--focus`). 날짜는 `min=2000-01-01`, `max=2100-12-31` |
| 카테고리 선택 (FR-013) | 네이티브 `<select>`, 옵션 순서 업무·개인·학습. 기본값은 "개인", 필터가 특정 카테고리면 그 카테고리 |
| 우선순위 선택 (FR-015) | 네이티브 `<select>`(`.select-input`), 옵션 순서 높음·보통·낮음. 기본값은 "보통". 추가 폼 `id="new-todo-priority"`, 편집 폼 `edit-priority-<id>`. 요청 중에는 비활성화 |
| 카테고리 필터 (FR-014) | 입력 폼과 목록 사이, `role="group"` + `aria-label="카테고리 필터"`. 버튼 4개(전체·업무·개인·학습) + 개수(`tabular-nums`, `.sr-only` "개"). 선택은 `aria-pressed="true"` + `.is-selected`(`--surface` 배경, 1px `--line-strong` 테두리, `--ink` 글자). 비선택은 고스트(`--slate`, 호버 `--hover`). 필터 기준으로 완료율·빈 상태를 계산하고, 빈 필터는 "<카테고리> 할 일이 없습니다." 안내 |
| 완료 상태 필터 (FR-017) | 카테고리 필터 바로 아래 줄(`.filters` 세로 묶음, 간격 `--space-1`), `role="group"` + `aria-label="완료 상태 필터"`. 버튼 3개(전체·진행 중·완료) + 개수. 스타일은 카테고리 필터와 같은 `.filter-group` + `.filter-btn`(새 색 없음). 두 줄 모두 앞에 보이는 라벨 `.filter-label`("카테고리"/"상태", `--text-sm`, `--slate`, 너비 4em, `aria-hidden` — 그룹 이름과 중복 낭독 방지)을 두어 "전체" 버튼 두 개를 구분하고, 버튼 묶음 `.filter-options`는 라벨 오른쪽 칸 안에서 줄바꿈한다(360px 이상 한 줄, 340px에서는 카테고리 줄만 두 줄). 두 필터는 AND로 적용하고, 상태 개수는 현재 카테고리 안에서 센다. 완료율은 상태 필터와 무관하게 카테고리 기준. 상태 필터 때문에 카드가 빠지면 입력창으로 포커스, "완료" 필터에서 추가하면 "전체"로 복귀 |
| 작업 카드(Task Card) | `--surface` 배경, 1px `--line` 테두리, 그림자 없음. 완료 시 배경을 비워(`--paper`가 비침) 뒤로 물러나고 텍스트는 `--slate` + `--pine` 취소선(1.5px). 카드 안 요소에 키보드 포커스가 있으면(`:has(:focus-visible)`) 테두리를 `--line-strong`으로 바꿔 현재 위치를 보여 준다 |
| 카드 보조 정보 줄 | 작업 텍스트 아래 `.todo-meta`: 카테고리 라벨 → 우선순위 → 마감 표시 순서, 간격 8px, 좁으면 줄바꿈 |
| 카테고리 라벨 (FR-013) | `.todo-category`: `--text-sm`, `--slate`, 1px `--line` 테두리, `--radius-segment`. **카테고리별 색을 쓰지 않는다**(색상 하나에 의미 하나, spec-review R-31) |
| 우선순위 배지 (FR-015) | `.priority-badge.is-<high\|medium\|low>`: 높이 22px, `--text-xs` 500, `--radius-segment`, 우선순위 토큰의 글자색 + 옅은 배경(spec-review R-47, R-40 대체). **색과 함께 항상 글자("높음" 등)를 표시**하고 스크린 리더용 `.sr-only` "우선순위 " 접두어를 둔다. 완료된 할 일의 배지는 배경을 비우고 1px `--line` 테두리 + `--slate`로 강조를 내려놓는다. 카드 텍스트 아래 `.todo-meta` 줄에 둔다 |
| 완료 상태 필터 탭 (대시보드) | `<fieldset class="filter-group">` + `.sr-only` `<legend>`"완료 상태 필터". `--paper` 배경 + 1px `--line` 테두리의 묶음 안에 버튼 3개(전체·진행 중·완료, `aria-pressed`, 개수는 통계 카드에 있으므로 표시하지 않음). 선택은 `--surface` + `--line-strong` 테두리 + `--ink`. 모바일은 3등분, 880px 이상은 내용 너비 |
| 빈 상태 (대시보드) | 점선 칸 안에 40px 문서 아이콘(`--line-strong` 선, `aria-hidden`) → 제목(500) → 설명(`--text-sm` `--slate`). 할 일 없음: "아직 할 일이 없습니다", 진행 중 필터: "진행 중인 할 일이 없습니다", 완료 필터: "완료한 할 일이 없습니다" |
| 목록 정렬 (FR-016) | 화면 목록은 항상 높음 → 보통 → 낮음, 같은 우선순위 안은 생성순. 완료 여부와 무관하고 정렬 전환 UI는 없다. 우선순위를 바꾸면 카드가 새 위치로 이동한다(애니메이션 없음) |
| 마감 표시 (FR-012) | 우선순위 옆 `<time dateTime="YYYY-MM-DD">`, `--text-sm`. 기본 "M월 D일 마감"(`--slate`), 오늘이면 "오늘 마감"(`--ink`, 500), 지났고 미완료면 "N일 지남"(`--danger`, 500). 완료된 할 일은 강조하지 않는다(`--slate`, 400). 판단 기준은 브라우저 현지 날짜(PRD D-8) |
| 카드 보조 버튼 | 수정·삭제·취소는 고스트 버튼(테두리 없음, `--slate`). 호버 시 `--hover` 배경, 삭제는 호버·포커스 시 `--danger` |
| 편집 모드 | 카드 테두리를 `--line-strong`으로. 1줄: 입력창 / 2줄: "카테고리" select, "우선순위" select, "마감일" 날짜 입력 + "마감일 지우기"(고스트, 마감일이 없으면 비활성화), 오른쪽에 저장(주요) + 취소(고스트). 텍스트·마감일·카테고리·우선순위 중 바뀐 필드만 한 번에 보내고, 모두 그대로면 요청하지 않는다 |
| 입력 검증 오류 (FR-001, FR-004, FR-010) | 텍스트 입력 바로 아래 `.field-error`(`--text-sm`, `--danger`, `tabular-nums`) 한 줄 + `role="alert"`. 입력창은 `aria-invalid="true"`이고 포커스가 없을 때 테두리 `--danger`(포커스 중에는 `--focus` 유지). 빈 값·공백만은 제출 시도 후에만, 100자 초과는 입력 즉시 "(현재 N자)"와 함께 표시. 문구와 기준은 서버와 같다(`src/todoText.ts`). 추가 폼·편집 폼 공통 |
| 빈 상태 | 점선 테두리 안내 문구: 다음 행동(입력 후 Enter)을 알려 준다. 필터 결과가 비면 조건을 문장에 담는다: "<카테고리> 할 일이 없습니다." / "[<카테고리> 중 ]진행 중인 할 일이 없습니다. 모두 완료했습니다." / "[<카테고리> 중 ]완료한 할 일이 없습니다. 할 일을 체크하면 여기에 모입니다." |
| 로딩 (FR-011) | 카드 높이(56px)의 `--track` 색 스켈레톤 3개(`aria-hidden`) + `.sr-only` 안내 문장(`aria-live="polite"`). 로딩 중에는 진행률을 숨기고 추가 버튼을 비활성화한다 |
| 목록 불러오기 실패 (FR-011) | `--surface` 카드 + 1px `--danger` 테두리, `role="alert"`. 제목(무엇이 실패했는지) → 원인 문장(`--slate`) → 주요 버튼 "다시 시도" |
| 동작 실패 알림 (FR-011) | 입력 폼 아래 한 줄 카드, 1px `--danger` 테두리, `role="alert"`. "무엇을 하지 못했습니다. + 원인" 형식, 오른쪽에 고스트 "닫기" 버튼 |
| 추가 요청 중 | 추가 버튼 문구를 "추가 중"으로 바꾸고 비활성화, 입력창은 읽기 전용. 제출 직후 포커스는 입력창 |

## 6. 반응형 (Responsive Breakpoints)

| 조건 | 변화 |
| --- | --- |
| 기본 | 최대 너비 600px 단일 열, 상하 48px 여백 |
| `min-width: 880px` | 2열 대시보드(왼쪽 300px sticky + 오른쪽 목록), 최대 너비 1040px |
| `max-width: 600px` | 여백을 32px/16px로 축소 |
| `pointer: coarse` | 버튼·필터 버튼·편집 입력·카테고리·우선순위 select·날짜 입력·추가 버튼 높이 44px (터치 대상 크기) |
| `max-width: 359px` | 카드의 수정·삭제 버튼을 다음 줄 오른쪽으로 내림. 입력 폼·편집 폼의 2줄은 `flex-wrap`으로 필요할 때만 줄바꿈 |

## 7. 접근성 (Accessibility Rules)

- 모든 조작 요소는 `:focus-visible`에서 3px `--focus` 외곽선(offset 2px)을 표시한다. 텍스트 입력창만 offset 0 + 테두리도 `--focus`로 바꾼다.
- 체크박스는 네이티브 `<input type="checkbox">` + `appearance: none`, 작업 텍스트는 `<label>`로 연결한다.
- 수정·삭제 버튼의 `aria-label`에 작업 내용을 포함한다.
- 편집 저장/취소 후 해당 작업의 "수정" 버튼으로 포커스를 복귀하고, Esc는 편집을 취소한다(텍스트·날짜 입력 모두, 폼에서 처리).
- 날짜 입력은 보이는 `<label htmlFor>`로 연결한다("마감일 (선택)", 편집 모드 "마감일"). "마감일 지우기"를 누르면 버튼이 비활성화되므로 포커스를 날짜 입력으로 옮긴다.
- 마감 표시는 색만으로 구분하지 않는다. "오늘 마감", "N일 지남" 문구 자체가 상태를 말한다.
- 카테고리 select는 보이는 `<label htmlFor>`("카테고리")로 연결한다. 필터 버튼은 `aria-pressed`로 선택 상태를, 버튼 이름(예: "업무 2개")으로 개수를 전달한다.
- 우선순위 select도 보이는 `<label htmlFor>`("우선순위")로 연결한다. 카드의 우선순위는 색이 아니라 글자("높음" 등)로 상태를 말한다.
- 우선순위를 바꿔 카드가 다른 위치로 옮겨져도 저장 후 포커스는 옮겨진 카드의 "수정" 버튼으로 간다(같은 `key`, spec-review R-39).
- 편집으로 카테고리를 바꿔 현재 필터에서 빠지면 "수정" 버튼이 사라지므로 새 할 일 입력창으로 포커스를 옮긴다(삭제와 같은 규칙, spec-review R-30).
- 삭제 후에는 새 할 일 입력창으로 포커스를 이동한다.
- 입력 검증 오류는 색만으로 알리지 않는다. 문구를 `role="alert"`로 읽어 주고, 입력창을 `aria-describedby`로 문구와 연결하며, 제출에 실패하면 포커스를 해당 입력창에 둔다.
- `prefers-reduced-motion: reduce`에서는 전환 효과와 스켈레톤 애니메이션을 끈다.
- 추가 버튼으로 제출해도 포커스는 입력창으로 돌아간다(버튼이 비활성화되며 포커스를 잃지 않도록).
